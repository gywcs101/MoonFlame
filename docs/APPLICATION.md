## 项目简介

MoonFlame 用纯 MoonBit 实现性能剖析结果的「最后一公里」：读取折叠栈（folded stack）文本，聚合成调用树，计算每个函数的自身耗时与累计耗时，输出一张可交互的静态 SVG 火焰图。它不依赖 Go、Node 或任何运行时，产物是单个可直接分享、可嵌入 README 的文件。

项目不重复实现采样——采样与格式归一由现有工具（如 moon-pprof、perf、py-spy）完成，MoonFlame 专注于把这些工具产出的数据变成一张人一眼能看懂的图。

## 项目方向与通用性说明

- **方向**：开发者工具 / 性能可视化基础设施，形态为「可复用库 + 单一命令行工具」。
- **格式通用性**：输入采用折叠栈这一跨语言中间格式。Linux `perf`、`py-spy`（raw）、`async-profiler`（collapsed）、MoonBit 的 `moon-pprof`（`pprof2folded`）均可产出该格式，因此本工具不绑定任何语言、平台或工具链。
- **运行通用性**：渲染器本身零第三方依赖，代码可编译到 wasm / wasm-gc / js / native 多个后端；既可当 CLI 用，也可作为库被其他工具调用。
- **生态位置**：现有可视化方案（`go tool pprof`、speedscope、Firefox Profiler）都需要额外运行时或浏览器会话；MoonFlame 补的是「单文件、零环境、可归档」这一空缺。

## 预期使用场景

1. **MoonBit 项目性能优化闭环**
   用 `moon-pprof profile --wasm-gc` 采样得到 `.pb.gz`，经 `pprof2folded` 转成折叠栈后交给 MoonFlame 出图；定位热点、优化代码、再次出图与上一版对比，确认改进是否生效。全程不需要修改被测程序。

2. **跨语言统一可视化**
   团队内不同项目分别用 perf（Linux）、py-spy（Python）、async-profiler（JVM）采样。只要各自导出折叠栈，就能用同一个工具、同一种样式出图，避免为每种语言安装并学习一套独立的 GUI 或 Web 查看器。

3. **构建与 CI 流水线的阶段耗时分析**
   在构建脚本中用轻量插桩记录各阶段耗时（如 `build;compile 1250`），生成折叠栈后出图，一眼看出编译、链接、打包哪一步是瓶颈；生成的 SVG 也可作为 CI 产物归档，便于对比历史版本。

4. **受限环境与文档场景下的离线出图**
   在内网、无 Go/Node 的机器上，或需要把性能图贴进 README、设计文档、复盘报告时，输出单个 SVG 文件即可完成分享与版本控制，无需接收方安装任何工具。

## 拟实现的核心功能

- **折叠栈解析**：逐行读取，容忍超长单行与极深栈，处理空帧名等异常输入；
- **调用树聚合**：同父同名节点合并并累加权重，保留自顶向下的调用关系；
- **耗时计算**：自身耗时与累计耗时，并输出文本版 Top-N 热点清单；
- **深度限制与深部合并**：真实递归程序的栈可达数千层，超出 `--max-depth` 的部分合并为合成节点，保证父节点宽度恒等于子节点宽度之和，避免布局出现空洞；
- **布局算法**：支持 icicle 与火焰图两种朝向，按值比例切分，并消除浮点累加误差；
- **SVG 输出**：矩形 + 悬停提示、同名同色、XML 转义与文件体积控制；
- **差异对比**：支持两份剖面比对，突出变宽与变窄的函数；
- **确定性输出**：同输入必得同输出，便于快照测试和版本间对比；
- **测试覆盖**：围绕解析、聚合、布局、限深等核心逻辑编写快照测试与边界用例。

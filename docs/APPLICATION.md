## 项目简介

MoonFlame 用**纯 MoonBit** 完成性能剖析的「最后一公里」：读取折叠栈（folded stack）文本，
聚合成调用树，计算每个函数的自身耗时与累计耗时，输出一张**自带交互功能的静态 SVG 火焰图**。

产物是**单个文件**：不依赖 Go / Node / 任何运行时，双击即看，可直接贴进 README、设计文档或 CI 归档。
**它不做采样**——采样与格式归一交给上游工具（`moon-pprof`、`perf`、`py-spy`、`async-profiler`），
MoonFlame 只负责把数据变成人一眼能看懂的图。这条边界让它天然跨语言、跨平台。

## 项目方向与适用场景

- **方向**：MoonBit 开发者工具 / 可复用的性能可视化基础设施（库 + 单一命令行工具）。
- **格式通用**：输入是跨语言中间格式，不绑定任何语言或工具链。
- **运行通用**：核心库零第三方依赖，可编译到 wasm / wasm-gc / js / native 四个后端；
  105 个核心测试在四个后端上均通过。
- **适用场景**：MoonBit 项目性能优化闭环；跨语言统一可视化；CI 阶段耗时分析与回归监控；
  内网 / 离线环境下出图并随文档分发。

## 现有基础（均已完成并验证）

| 能力 | 说明 |
| --- | --- |
| **折叠栈解析** | 容忍超深栈（实测 7254 层）、超长单行（181K 字符）、空帧名等真实脏数据 |
| **调用树聚合** | 同父同名合并；自身 / 累计耗时；**限深合并**（超额部分并入 `(deeper)` 而非丢弃，否则深层耗时会被错算到最后一个可见帧） |
| **文本报告** | `hotspots` 热点榜、`callers` / `callees` 调用关系、`delta` 差异排行（子命令形态） |
| **布局** | 火焰图 / 冰柱两种方向；父宽严格等于子宽之和；消除亚像素裂缝 |
| **可交互 SVG** | 经典暖色调色板 + 内嵌脚本：悬停信息栏、点击缩放、`Ctrl-F` 搜索、命中占比 |
| **差异火焰图** | 红 = 变多、蓝 = 变少、白 = 无变化 |
| **名称归一化** | 自动还原上游未还原的符号名（`build__strings` → `build_strings`），**解析层原样保留** |
| **确定性输出** | 同输入必得逐字节相同的 SVG，可做快照测试与版本间对比 |

## 技术要点

- **边界清晰**：根包纯计算、零依赖；文件 IO 只出现在入口包；参数解析独立成包可脱离文件系统测试。
- **限深必须合并**：递归程序的栈可达数千层，丢弃会misattribute 耗时，合并才能守住「父宽 = 子宽之和」。
- **实测驱动的结论**：发现上游采样密度取决于**函数调用频率**而非运行时长（调用密集 ≈600 样本/秒、
  循环密集 ≈42 样本/秒，相差 14 倍），因此短于约 25ms 的函数可能采不到——这条已写入 README 的限制。
- **数据可信**：采样结果与 `go tool pprof` 交叉验证，Top-N 数值完全一致。
- **接口面控制**：顶层只有 5 个选项/开关，一切文本报告做成子命令，功能增长不使顶层界面膨胀。

## 参考来源与开源合规

**未复制任何第三方源码。** 图形外观与交互行为对齐 Brendan Gregg 的 FlameGraph，但仅对齐
**功能规格**（配色数值公式、交互语义、几何常量）——该项目采用 CDDL-1.0（文件级弱 copyleft，
非宽松许可），为避免许可证混用，其源码一行未使用，MoonBit 与 JavaScript 实现全部原创。

其他参考：`mizchi/moon-pprof`（Apache-2.0，上游数据来源）、`google/pprof`（Apache-2.0，交叉验证基准）、
`testdata/official-sample.wasm`（来自 moon-pprof 仓库，已注明来源）。
